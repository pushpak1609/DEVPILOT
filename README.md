# DevPilot

AI-powered code assistant that lets you chat with any GitHub repository. DevPilot indexes your codebase, retrieves the most relevant code chunks for your question (RAG), and streams grounded answers back with file citations.

## Features

- 🔗 **GitHub OAuth login** — connect your repos securely
- 🧠 **RAG-grounded chat** — answers are backed by actual code from your repository, with file/line citations
- ⚡ **Real-time streaming** — token-by-token responses over SSE
- 🗂️ **Session management** — rename, delete, and auto-titled chat sessions (title is generated by the LLM after your first exchange)
- 📊 **Repository indexing** — chunking + embeddings pipeline with live indexing status
- 🎨 **Clean, dark-mode UI** — built with Next.js, Tailwind, and shadcn-style components
- 🐳 **Fully containerized** — one command runs the database, backend and frontend

## Tech Stack

**Backend**
- Java 21, Spring Boot 4.1.1, Spring AI
- PostgreSQL + [pgvector](https://github.com/pgvector/pgvector) for vector similarity search (HNSW index, cosine distance)
- [Groq](https://groq.com/) (OpenAI-compatible API) for chat streaming
- [Google Gemini](https://ai.google.dev/) for embeddings
- GitHub OAuth2 for authentication

**Frontend**
- Next.js (App Router) + React
- TypeScript, Tailwind CSS
- TanStack Query for server state
- Server-Sent Events (SSE) for streaming chat

**Infra**
- Docker (multi-stage, non-root images) and Docker Compose
- GitHub Actions CI with Trivy vulnerability scanning
- GitHub Container Registry (GHCR) for published images

## Architecture

```
User → Next.js frontend → Spring Boot backend
                              │
                              ├─ GitHub API (fetch repo files)
                              ├─ Gemini (generate embeddings)
                              ├─ pgvector (store/retrieve code chunks)
                              └─ Groq (stream chat completions)
```

**Chat flow:** `ChatController` → `ChatService.streamReply()` → `CodeContextRetriever` (RAG via pgvector) → `ChatPromptBuilder` → `ChatStreamHandler` (SSE via `SseEmitter`)

## Getting Started (Docker)

### Prerequisites

- Docker Desktop (with Compose)
- A [Groq API key](https://console.groq.com/keys)
- A [Google AI Studio API key](https://aistudio.google.com/apikey) (for embeddings)
- A [GitHub OAuth App](https://github.com/settings/developers) for local use, with this callback URL:
  `http://localhost:8080/login/oauth2/code/github`

### 1. Clone the repo

```bash
git clone https://github.com/pushpak1609/DEVPILOT.git
cd DEVPILOT
```

### 2. Create a `.env` file in the repo root

```
GEMINI_API_KEY=
GROQ_API_KEY=
GITHUB_CLIENT_ID=
GITHUB_CLIENT_SECRET=
TOKEN_ENCRYPTOR_PASSWORD=
TOKEN_ENCRYPTOR_SALT=
```

- Fill in each value. `TOKEN_ENCRYPTOR_SALT` must be a hex string and `TOKEN_ENCRYPTOR_PASSWORD` a long random string.
- `.env` is gitignored. Never commit it.

### 3. Start everything

```bash
docker compose up -d --build
```

This starts three containers:

| Service | What it runs | Port |
|---|---|---|
| `postgres` | PostgreSQL 16 + pgvector (data kept in a named volume) | 5433 (host) |
| `backend` | Spring Boot API | 8080 |
| `client` | Next.js frontend | 3000 |

### 4. Open the app

Visit `http://localhost:3000`, log in with GitHub, connect a repository, wait for indexing to finish, and start chatting.

### Useful commands

```bash
docker compose ps                 # status of all services
docker compose logs -f backend    # follow backend logs
docker compose down               # stop and remove containers (data volume is kept)
docker compose down -v            # also delete the database volume (data is lost)
```

### Notes

- The backend reads all secrets and settings from environment variables. No secrets are stored in the repo or inside the images.
- For plain `http://localhost`, Compose overrides the session cookie to `SameSite=Lax` and `Secure=false`. The deployed setup (separate frontend and backend domains over HTTPS) uses `SameSite=None; Secure`.
- `NEXT_PUBLIC_API_BASE_URL` is baked into the frontend at build time. Compose passes `http://localhost:8080`. For another backend URL, rebuild with `--build-arg NEXT_PUBLIC_API_BASE_URL=<url>`.

## Run without Docker (development)

Requires Java 21+, Node.js 22+ and a running Postgres with the `vector` extension (you can run just the database with `docker compose up -d postgres`).

Export the same variables as in the `.env` file above in your shell, then:

```bash
# backend (http://localhost:8080)
cd backend
./mvnw spring-boot:run

# frontend (http://localhost:3000)
cd client
npm install
npm run dev
```

## Containers and CI

**Images**
- Multi-stage builds: backend ≈ 263 MB, frontend ≈ 82.5 MB (compressed)
- Both run as a non-root user (`app` for the backend, `nextjs` for the frontend)
- Dependency layers are ordered for build caching (a cold build took about 132 s, a fully cached rebuild about 1.3 s)
- The Next.js app uses `output: "standalone"` so only the files it needs reach the final image

**GitHub Actions** (`.github/workflows/docker.yml`) runs on every push:

1. Builds the backend and frontend images
2. Scans them with Trivy and fails the build on any fixable CRITICAL vulnerability
3. Publishes the images to GHCR, tagged with the commit SHA and the branch name

```bash
docker pull ghcr.io/pushpak1609/devpilot-backend:<tag>
docker pull ghcr.io/pushpak1609/devpilot-client:<tag>
```

**Vulnerability scanning (Trivy, HIGH and CRITICAL findings with a fix available)**

| Image | Before | After |
|---|---|---|
| Backend | 17 (4 CRITICAL) | 11 HIGH, 0 CRITICAL |
| Frontend | 16 (3 CRITICAL) | 0 |

What changed: overrode Tomcat to 11.0.26 (Spring Boot 4.1.1 manages 11.0.24), upgraded Next.js 16.3.3 to 16.4.1, removed npm from the runtime image, and refreshed base images. The remaining 11 backend findings are Jackson and Guava denial-of-service issues that are tracked and will be fixed when a Spring Boot release includes patched versions.

## Security Notes

- Secrets (API keys, OAuth credentials, encryption password and salt) are supplied only through environment variables or the gitignored `.env` file. Never commit them.
- Images contain no secrets and run as non-root users.
- OAuth tokens are encrypted at rest using the configured encryptor password and salt. Set your own values, don't reuse examples.
